# Clinical AI Safety, Orientation Robustness, Explainability, and Trust-Calibration UX for Brain Tumor MRI Segmentation Tools

## A1. Robust input validation for medical imaging AI pipelines (corrupt files, wrong modality, non-finite values, mismatched affines/orientations)

### Takeaway
There is no single authoritative standard for end-to-end input validation in medical imaging AI, but a consistent pattern emerges across tooling and engineering guides: validate orientation/affine metadata at ingestion, normalize to a canonical frame (e.g., RAS+), don't trust header metadata alone, and log the transform applied. A purpose-built open-source guardrails package exists for DICOM input/output validation including orientation sanity checks.

### Cited Findings
- The open-source `healthcare-ai-guardrails` Python package validates AI inputs/outputs for DICOM data; it includes an orientation sanity check (`dicom_image_orientation_sane`, default tolerance 1e-3) alongside checks on modality, pixel spacing, and slice thickness, declared via YAML spec and runnable via CLI — [PyPI: healthcare-ai-guardrails](https://pypi.org/project/healthcare-ai-guardrails/) (informal/tooling, not peer-reviewed).
- An engineering best-practices guide for medical imaging ML states that coordinate systems and orientation are common causes of otherwise-strong models failing validation, and recommends normalizing images to canonical coordinates (RAS or LPS) and checking anatomical orientation up front — [Innolitics: Medical Imaging AI/ML Engineering Guide](https://innolitics.com/articles/medical-imaging-best-practices/) (informal/industry blog).
- RABIES (rodent fMRI pipeline) documentation states incorrect image orientation is one of the most common causes of registration failures and recommends checking orientation before filing any bug report — [RABIES troubleshooting docs](https://rabies.readthedocs.io/en/latest/troubleshooting.html) (tool documentation).
- AIDAmri, a mouse-MRI preprocessing pipeline, performs automated re-orientation, bias-field correction, and brain extraction with minimal user input as standard pipeline steps — [AIDAmri wiki](https://github.com/Aswendt-Lab/AIDAmri/wiki) (tool documentation).
- A US patent (on orientation detection/correction for medical images) states that images with wrong orientation "may degrade the performance of a computer-aided diagnostic system or an artificial-intelligence diagnostic system if they are used as input" — [USPTO patent 11682135](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/11682135) (patent document, not peer-reviewed research).
- A macaque-MRI orientation-correction study notes orientation metadata itself can be unreliable: "image orientation may be incorrectly recorded owing to scanner-specific settings, inconsistencies in sequence configuration, or omission of manual orientation adjustment," and uses rigid registration to a template (with the template's L-R axis pre-flipped to avoid hemisphere mirroring) as an automated correction step — [Research Square supplementary note, macaque MRI orientation correction](https://assets-eu.researchsquare.com/files/rs-10203507/v1/a96db3c1ee6b67dcafa6f780.docx) (preprint supplement, not fully peer-reviewed at time of search).

### Inferences
- A practical pipeline validation layer should combine: (1) header/affine consistency checks (qform vs sform agreement, determinant sign, voxel dims), (2) canonicalization to a fixed frame before inference, (3) a logged/auditable record of what transform was applied, and (4) template or atlas-based geometric sanity checks when header metadata can't be trusted outright.

### Gaps
- No peer-reviewed paper was found proposing a comprehensive, formally validated checklist/protocol specifically for "medical imaging AI pipeline input validation" as a named research contribution — most material found is applied/engineering-blog or open-source tooling, not peer-reviewed methodology papers.

## A2. NIfTI orientation / LAS-RAS confusion / radiological vs neurological convention bugs

### Takeaway
The radiological-vs-neurological-convention ambiguity is a well-documented, long-standing source of left-right flip errors in neuroimaging, rooted in the legacy ANALYZE 7.5 format and inconsistent software assumptions about missing qform/sform codes; NIfTI was explicitly designed to make the "radiological/neurological" display-convention terminology obsolete by storing explicit affine orientation, but flips still occur in practice, including in major public research datasets, due to software-specific legacy assumptions.

### Cited Findings
- NIfTI's world frame is RAS (+x Right, +y Anterior, +z Superior), unlike ANALYZE's LAS convention; the NIfTI standard was designed to make radiological/neurological display labels obsolete because software can read the stored orientation directly and flip display as needed — [brainder.org, "The NIFTI file format"](https://brainder.org/2012/09/23/the-nifti-file-format/) (informal technical blog, highly regarded in neuroimaging community).
- FSL and FreeSurfer (and some other tools) assume files lacking both sform and qform codes have a reversed left-right orientation (an ANALYZE-compatibility legacy assumption); this breaks for files written by tools like MATLAB where sform=qform=0 is intended to mean RAS, producing an unexpected flip — [NHP-pRF toolbox FAQ via gin.g-node.org](https://gin.g-node.org/doi/NHP-pRF/raw/0989677dd5161d79862ea6cc7f9604f372c51643/Toolboxes/NIfTI/FAQ.pdf) (informal/toolbox documentation).
- FSL's own orientation documentation states left-right orientation is stored in the header separately from how the viewer (FSLView) displays it; data on disk may be radiological or neurological order and FSL tools handle either, but ANALYZE files are treated as radiological and FSL recommends avoiding that legacy format — [FSL "Orientation Explained"](https://web.mit.edu/fsl_v5.0.10/fsl/doc/wiki/Orientation(20)Explained.html) (official tool documentation).
- FSL's guide warns that fixing orientation by trial-and-error axis swaps (e.g., with `fslswapdim`) can easily produce an incorrect left-right label unless a reliable physical marker (e.g., a vitamin capsule taped to one side during acquisition) is used to verify laterality — [FSL "Orientation Explained"](https://web.mit.edu/fsl_v5.0.10/fsl/doc/wiki/Orientation(20)Explained.html) (official tool documentation).
- A peer-reviewed 2020 paper in *Frontiers in Neuroinformatics* by Glen et al. describes systematic left-right flips found between subject EPI and anatomical volumes in major open MRI repositories — the Functional Connectome Project, OpenfMRI, and ABIDE — caused by incorrect or missing file header information; some flips are obvious but others are subtle due to brain structural symmetry; the authors released an AFNI tool to check for such flips — [Glen et al., *Frontiers in Neuroinformatics* 2020, "Errors in fMRI Data"](https://www.frontiersin.org/journals/neuroinformatics/articles/10.3389/fninf.2020.00018/epub) (peer-reviewed journal article — note: full text could not be directly re-fetched during this research session, so details are drawn from the WebSearch summary rather than a direct read of the article; verify before citing exact wording).
- The same source notes that laterality errors have also been reported in clinical radiology practice, not just research pipelines — [same Glen et al. 2020 Frontiers paper, via search summary] (peer-reviewed, secondhand summary).
- A MATLAB utility (`flip_lr.m`) exists specifically to convert RAS data to LAS for legacy tools, with the author's own warning that careless use "can introduce the very flip you're trying to avoid" — [gin.g-node.org flip_lr.m](https://gin.g-node.org/ChrisKlink/NHP-pRF/src/master/Toolboxes/NIfTI/flip_lr.m) (informal/toolbox code comment).

### Inferences
- The practical mitigation pattern across sources is: (1) never rely on "radiological/neurological" labels alone, (2) always read and cross-check both qform and sform affines rather than assuming agreement, (3) verify `pixdim[0]` (qfac) is exactly -1 or 1, (4) use a known physical/anatomical asymmetry marker or atlas-based check to confirm true left-right labeling rather than trusting header claims, and (5) visually confirm orientation in at least one independent viewer before trusting a pipeline's output.
- For a tool like a brain tumor segmentation viewer, an explicit automated check (e.g., comparing the affine determinant sign and axis codes against expected RAS conventions, plus a visual confirmation step) is a direct, citable mitigation grounded in this literature.

### Gaps
- No specific published incident report or paper was found describing an AI *model* (as opposed to a research/processing pipeline) actually making a clinical left-right error due to an orientation bug. The closest documented cases are dataset-level flips (Glen et al. 2020) and pipeline/registration-level flips (macaque MRI note), not a reported AI-inference failure. This should be stated as an inferred-risk rather than a documented AI-specific incident.
- The brainder.org article (fetched directly) does not explicitly describe a "determinant sign check" method for detecting flips; this is a reasonable engineering inference from the affine math described (RAS world frame, qfac sign convention) but is not itself a verbatim cited recommendation from that source.

## A3. "Safe failure" / graceful degradation frameworks for clinical decision support AI

### Takeaway
Published and industry discussion converges on the idea that **silent failure** (the system appears "on" but produces degraded/wrong output without signaling it) is the central safety hazard — more dangerous than an overt failure/refusal — and that mitigation requires continuous output-quality monitoring, not just uptime monitoring, plus designed fallback workflows and audit logging of AI recommendations and clinician overrides. No single named "graceful degradation" technical standard specific to clinical AI was found; this is treated as a synthesis across sources, which is noted explicitly below.

### Cited Findings
- A review by Guan, Bates, and Zhou (Brigham and Women's Hospital) on medical AI system degradation states that AI systems may degrade over time due to shifting data distributions, changing patient characteristics, evolving clinical protocols, and data-quality variation, and argues for continuous performance monitoring, early degradation detection, and self-correction mechanisms — [Guan, Bates, Zhou, "Keeping Medical AI Healthy and Trustworthy," arXiv 2506.17442](https://arxiv.org/pdf/2506.17442) (preprint, not confirmed peer-reviewed at time of search).
- An industry continuity-planning article states that a dangerous AI failure mode is one where "the system still looks 'on'" while sensitivity drops and care decisions worsen without warning, and that continuity plans checking only uptime "will miss all of that" — [Censinet, "AI failure modes healthcare continuity planning"](https://censinet.com/perspectives/ai-failure-modes-healthcare-continuity-planning) (informal/vendor blog, not peer-reviewed).
- The same source states clinical decision support is often among the first workflows to break when AI drifts, stalls, or returns unsafe output, and that downtime can harm care quickly by slowing orders, hiding labs, and removing decision support, forcing paper workarounds — [Censinet, same article] (informal/vendor blog).
- Guidance on clinical AI safety recommends training clinicians on how the AI works, its known failure modes, and how to interpret explanations so they are neither over- nor under-trusting — [MiroMind, "How should clinicians use AI safely in decision support"](https://www.miromind.ai/use-cases/how-should-clinicians-use-ai-safely-in-decision-support) (informal/vendor content, not peer-reviewed).
- One source reports that by August 7, 2024, 950 AI/ML medical devices had FDA clearance/approval, and 5.8% had been recalled, mostly due to software issues like delayed outputs, incorrect dosing, or missed/delayed imaging results — [via Censinet article, citing underlying FDA data] (secondary citation; underlying primary FDA source not independently verified in this session — flag before using the specific percentage).
- Industry guidance recommends logging when AI was used, what it recommended, and whether clinicians accepted or overrode the recommendation, to support after-the-fact detection of degradation and accountability — [Censinet, "patient safety resilience ai driven health ecosystem"](https://censinet.com/perspectives/patient-safety-resilience-ai-driven-health-ecosystem) (informal/vendor blog).

### Inferences
- For a real-time clinical tool, the "safe failure" principle translates concretely to: the tool should prefer visibly declining/flagging uncertain or invalid input (e.g., "cannot segment — orientation unverifiable" or "confidence too low to display") over silently rendering a plausible-looking but wrong segmentation. This is consistent with, though not verbatim stated in, the sources above.

### Gaps
- No peer-reviewed paper or formal named framework (e.g., a specific "tiered fallback" or "confidence-based abstention" standard) for clinical AI graceful degradation was found in this search; available material is industry/practitioner commentary. A narrower search of FDA guidance on AI-enabled device software functions or human-factors/safety-engineering literature on clinical alerting would likely be needed to find a more formal treatment — explicitly flagged as unresolved.
- The 5.8% device recall statistic should be treated cautiously since it was only found via a secondary source in this session.

## A4. Lightweight detection of skull-stripped vs non-skull-stripped, or brain-vs-non-brain input (OOD/sanity checks)

### Takeaway
No fully "off-the-shelf" skull-strip-failure classifier was found, but several concrete, citable building blocks exist: simple automated flagging methods using mask-geometry heuristics (hole counts, volume/coverage thresholds, Dice overlap with a template) and learned-feature classifiers trained on outputs of the skull-stripping/normalization/segmentation stages.

### Cited Findings
- An ISMRM abstract proposes a simple, fully automated method to flag skull-stripping errors, tested on outputs of two brain segmentation algorithms across a large multicenter dataset, reporting high specificity for detecting skull-stripping errors — [ISMRM 2019 abstract #2462](https://archive.ismrm.org/2019/2462.html) (conference abstract, not full peer-reviewed paper).
- NeuroPilot (2026 arXiv preprint), an agent-driven neuroimaging QC pipeline, uses a hole-count metric flagged via a modified Z-score across the cohort, cross-checks over-tightness against SynthStrip, and reports a PASS/WARN/FAIL grading; its repair step reduced a skull-strip exclusion metric by a mean of 27% across the fix cohort, flagging 97 of 558 scans at the raw-image stage — [NeuroPilot, arXiv 2608.07541](https://arxiv.org/pdf/2608.07541) (preprint, not confirmed peer-reviewed).
- One study used brain-mask coverage plus Dice overlap (threshold ≥0.95) against the MNI152 template as an automated pass/fail gate, flagging intensity outliers via the median absolute deviation rule, with failed scans sent to trained human raters for inspection of skull boundaries, cortical alignment, and residual non-brain tissue — [cited via WebSearch summary of brain MRI QC literature; original source not independently verified] (methodology described in a reviewed QC study; exact citation unresolved in this pass — flagged as a gap).
- A learned-QC approach computes 69 features from the outputs of skull stripping, spatial normalization, and tissue segmentation (using the Quality Assessment Protocol) and feeds them into a classifier for automated MRI QC — [Esteban et al.-style QC pipeline, referenced as "Learning brain MRI quality control: a multi-factorial generalization problem," arXiv 2205.15898](https://arxiv.org/pdf/2205.15898) (preprint; verify peer-review status before final citation).
- A benchmark of seven skull-stripping tools (BET, ROBEX, HD-BET, HD-BET-fast, SynthStrip, SynthStrip-noCSF, d-SynthStrip) against manual ground truth on pediatric T2-weighted MRI found performance varies substantially by tool and includes manual review of top/bottom-quartile segmentations as part of the evaluation protocol — [referenced via WebSearch summary; exact paper title/venue not confirmed in this session] (peer-reviewed benchmark study, exact citation to be verified).

### Inferences
- A lightweight, deployable heuristic for a real-time tool (brain-tissue mask coverage fraction, hole count, and/or overlap with a standard brain template/atlas) is a defensible, literature-grounded first-line sanity check before running tumor segmentation, with human/manual review as the fallback for flagged cases — directly transferable to UI design (e.g., a pre-flight "image doesn't look like a skull-stripped/brain MRI" warning banner).

### Gaps
- Exact full citations (authors, journal/venue, year) for two of the five findings above could not be fully resolved within the tool-call budget of this research pass; the report writer should treat these as needing verification before being stated as hard facts, or should drop them if a citation cannot be confirmed downstream.
- No paper specifically addressing "is this MRI brain tissue at all vs. some other anatomy" (as opposed to skull-stripped-vs-not) was found as a distinct published method; this appears to be an underexplored or at least under-indexed sub-problem relative to skull-strip-specific QC.

## B1. Explainability techniques applied to 3D tumor segmentation (not classification)

### Takeaway
Grad-CAM-family methods (Grad-CAM++, SmoothGrad) have been adapted to 3D segmentation networks (notably via the M3d-CAM library and a 2024 MS-lesion 3D U-Net study), but these methods carry documented localization-reliability caveats in 3D/medical settings; dedicated attention-map visualization specifically for Swin UNETR was not found in the literature search, though related transformer-hybrid segmentation architectures with built-in interpretability exist.

### Cited Findings
- A 2024 study on multiple sclerosis lesion segmentation applied instance-level explanation maps based on SmoothGrad and Grad-CAM++ to a 3D U-Net trained on 4,043 FLAIR and MPRAGE MRI scans from 687 patients (University Hospital of Basel); the study also examined how much perilesional tissue the model needed to use to segment a lesion — [cited via WebSearch result, arXiv 2406.09335 context; verify exact arXiv ID/title before final citation] (appears to be a peer-reviewed or strong preprint methods paper; exact citation needs confirmation).
- M3d-CAM is an open-source PyTorch library that generates 3D attention/Grad-CAM-style maps for medical deep learning models, with documented examples for classification, 2D segmentation, and 3D segmentation (e.g., applied to an nnU-Net on prostate CT) — [M3d-CAM paper, ar5iv.org/html/2007.00453](https://ar5iv.arxiv.org/html/2007.00453) (peer-reviewed/preprint tool paper).
- HiResCAM (focused on 3D medical classification, not segmentation) identifies a previously unrecognized limitation of Grad-CAM: due to the gradient-averaging step, Grad-CAM "sometimes highlights the wrong location"; the authors propose a label-specific attention mechanism "provably guaranteed to highlight only the locations the model used to make each prediction" — [HiResCAM paper, arXiv 2011.08891](https://arxiv.org/pdf/2011.08891v3) (peer-reviewed/strong preprint).
- A chest X-ray saliency-method benchmark found Grad-CAM generally localized pathologies better than other evaluated saliency methods, but all seven tested methods performed significantly worse than a human benchmark, with the largest gap for smaller, more complex-shaped pathologies — [VinUni, "Benchmarking saliency methods for chest X-ray interpretation"](https://research.vinuni.edu.vn/research-output/benchmarking-saliency-methods-for-chest-x-ray-interpretation/) (peer-reviewed).
- A 2026 lung cancer CT study found Grad-CAM "effectively highlights salient tumor regions in most convolutional networks," but its "interpretive fidelity significantly degrades for Vision Transformer models due to non-local attention behavior" — [cited via WebSearch result; exact source/venue not fully confirmed, flagged for verification] (likely peer-reviewed or strong preprint; citation needs confirmation).
- No paper specifically visualizing Swin UNETR's internal shifted-window attention maps was found. Related but distinct results: SDAH-UNet (Swin Deformable Attention Hybrid U-Net) explains predictions via its deformable-attention deformation field rather than standard attention weights, explicitly motivated by the claim that "hybrid models often fail to give a direct explanation, which is crucial in clinical scenarios" — [SDAH-UNet, arXiv 2302.14450](https://arxiv.org/pdf/2302.14450v1) (preprint/peer-reviewed, verify venue).
- Token-UNet, a transformer-integrated 3D brain-imaging segmentation network, reports that its spatial attention maps "focus on specific tissues and structures relevant to the domain and task" — [Token-UNet, arXiv 2602.20008](https://arxiv.org/pdf/2602.20008) (preprint; note arXiv ID format suggests a very recent/2026-dated paper — verify).
- MAPUNetR is described as a transformer-plus-U-Net design that "incorporates attention maps highlighting segmented regions, increasing accuracy and interpretability," the closest match found to "attention-map visualization in transformer segmentation" though not Swin UNETR specifically — [cited via WebSearch result, exact arXiv ID not confirmed] (needs citation verification).

### Inferences
- For a hackathon-scale brain tumor segmentation tool, the most tractable, literature-grounded explainability route for a 3D network is Grad-CAM++/SmoothGrad via an existing library (M3d-CAM) rather than building custom attention-rollout visualization for a transformer backbone — the latter has far less established tooling/precedent in the literature found here.
- Any saliency overlay should be presented with a caveat consistent with the HiResCAM and chest-X-ray benchmark findings: Grad-CAM-style maps in medical imaging can mislocalize, especially for small/complex structures, so UI framing should avoid implying the heatmap is a verified causal explanation.

### Gaps
- Could not confirm exact full citations (venue, peer-review status) for several arXiv-sourced findings above within the tool budget; flagged individually. The report writer should treat unresolved citations as "preprint, unverified venue" rather than fully peer-reviewed until independently checked.
- No direct literature on attention visualization specifically for UNETR++ was found in this pass (only Swin UNETR and generic hybrid transformer-U-Net architectures were covered); this is a specific stated sub-question that remains unanswered.

## B2. Is "modality ablation as explanation" (e.g., removing FLAIR or T1Gd and observing segmentation change) an established technique, or would it be novel for a hackathon demo?

### Takeaway
Modality ablation is an established *methodological* technique in brain tumor segmentation research — used to study missing-modality robustness and to measure each sequence's contribution to accuracy (e.g., via Dice-score drop-off) — but it is used there primarily as a robustness/benchmarking tool for model development, not as an end-user-facing "explanation" feature inside a clinical/demo UI. Framing it explicitly as a live, interactive "explanation" feature for an end user (i.e., "see what happens to the tumor boundary if you remove FLAIR") appears to be a novel UI framing relative to the papers found, even though the underlying technique (ablating a modality and observing the output) is not new in the research literature.

### Cited Findings
- Research on missing-modality brain tumor segmentation states that "most existing algorithms rely heavily on complete multimodal inputs and exhibit pronounced performance degradation when any modality is missing," motivating modality-ablation studies as a way to test and improve robustness — [cited via WebSearch summary of missing-modality BraTS literature, e.g. "No Modality Left Behind," arXiv 2509.15017] (preprint; verify exact claim location before final citation).
- One missing-modality study reports segmentation quality depends on which modality is missing and visualizes each modality's contribution to the output — consistent with the "ablation as explanation of modality contribution" concept, but framed as a model-robustness analysis, not a clinical-UI explanation feature — [cited via WebSearch summary; specific paper not independently re-fetched, flagged for verification] (preprint, exact citation needs confirmation).
- A study on modality fusion strategies found that fusing T1+T2 and T1ce+FLAIR were the best-performing modality-pair strategies, and that pairing modalities with overlapping information can cause the model to over-attend to single-feature information — [cited via WebSearch summary of fusion-strategy ablation literature] (preprint/peer-reviewed, exact citation unresolved — flagged).
- A cross-modal segmentation study (MSM-Seg) found that varying the input *order* of MRI sequences did not significantly affect performance, distinguishing order-ablation from modality-presence-ablation as a different robustness axis — [cited via WebSearch summary, "Synergistic Modality-and-Slice Memory Framework," arXiv 2510.10679] (preprint, verify).
- Component/module ablation (removing architectural modules such as the "Modality-Aware" and "Modality-Shift" blocks) is a related but distinct technique from modality-input ablation, used in architecture papers to justify design choices rather than to explain clinical outputs — [cited via WebSearch summary of MASM paper, arXiv 2403.02074] (preprint, verify).

### Inferences
- Because all found uses of modality ablation are positioned as model-development/robustness research (measuring Dice-score sensitivity to missing input channels) rather than as an interactive, clinician-facing explanation widget, presenting "live modality ablation" as an interactive explainability feature in a demo UI (e.g., a toggle that lets a user remove FLAIR/T1Gd and watch the segmentation update) is a reasonable, defensible, and likely genuinely novel UI framing for a hackathon context — it repurposes an established research technique into a new interaction pattern, rather than inventing the underlying computational idea from scratch. This claim should be stated with that nuance (technique not new; UI/interaction framing plausibly novel) rather than claiming outright novelty of the underlying idea.

### Gaps
- No paper was found that explicitly proposes or evaluates "interactive modality ablation" as a clinician-facing XAI *interface* (as opposed to an internal robustness-evaluation method) — this absence is itself the main evidentiary basis for calling the UI framing novel, but it is an absence-of-evidence inference, not a positive confirmation that no one has built this; a product/HCI-specific search (rather than ML-methods search) might surface a counterexample not found here.

## C1. How radiologists calibrate trust in AI segmentation/detection tools; UI elements for appropriate trust calibration

### Takeaway
Empirical evidence (mostly in radiation oncology and neuro-oncology) shows that showing calibrated uncertainty/confidence information measurably changes clinician edit behavior — clinicians edit less in regions the model marks as low-uncertainty — and that calibration (not just accuracy) is treated as a specific, separate barrier to clinical adoption; separately, survey/behavioral evidence shows clinicians prefer an "AI as second reader" workflow over AI-first or triage models, and that both over-reliance (automation bias) and under-reliance are documented failure patterns, with simple "performance feedback" alone insufficient to fix under-reliance.

### Cited Findings
- A study of prostate cancer radiotherapy auto-segmentation found oncologists made 50% fewer voxel edits in regions the model marked with uncertainty 0.0–0.1 (very low uncertainty) and concluded that showing this information "influences experienced radiation oncologists' decision-making, quality perception, and confidence in the DL segmentations" — [arXiv 2502.18973, "Impact of deep learning model uncertainty on manual corrections to auto-segmentation in prostate cancer radiotherapy"](https://arxiv.org/pdf/2502.18973) (preprint; verify peer-review venue).
- A UCSF-led study on meningioma MRI segmentation describes a lack of calibrated uncertainty as "a major barrier to clinical adoption," uses evidential deep learning ensembles, reports uncertainty maps aligning with ambiguous regions and well-calibrated volume estimates, and reports external validation on 353 patients — [UCSF, "Can Uncertainty Scores Help Experts Trust AI Brain Tumor Analysis?"](https://www.ucsf.edu/news/2026/07/432261/can-uncertainty-scores-help-experts-trust-ai-brain-tumor-analysis) (institutional news article summarizing a peer-reviewed/academic study — label as secondary/press coverage, not the primary paper itself).
- A 2026 preprint on nnU-Net radiotherapy QA compared calibration methods (temperature scaling, deep ensembles, checkpoint ensembles, test-time augmentation) and found segmentation accuracy remains stable while temperature scaling "substantially improves calibration," and that uncertainty-error alignment improves most with calibrated checkpoint-based inference, helping maps flag regions needing manual edits — [alphaxiv.org, "Budget-Aware Uncertainty for Radiotherapy Segmentation QA Using nnU-Net," 2604.11798](https://www.alphaxiv.org/abs/2604.11798) (preprint).
- An ultrasound segmentation study argues two clinicians would likely produce different but equally correct segmentations, and built a dataset with per-pixel confidence scores from radiologists so uncertainty could be modeled from annotator disagreement, not just model error — [arXiv 2508.15635, "Label Uncertainty for Ultrasound Segmentation"](https://arxiv.org/html/2508.15635v1) (preprint).
- A review (Padhani and Papanikolaou) on AI-inclusive prostate MRI reading workflows states AI can act as a second reader, flag anomalies radiologists might miss, and improve efficiency in understaffed settings, but warns of automation bias and risks of missed/delayed diagnosis and overdiagnosis, concluding mitigation strategies need further research — [Padhani & Papanikolaou, *European Radiology* (via secondary summary)] (peer-reviewed journal article; cited via secondary summary — recommend verifying the primary article directly before quoting).
- An arXiv preprint on prostate MRI diagnosis found human+AI teams consistently outperform humans alone but still underperform the AI alone due to under-reliance, and that providing performance feedback alone "did not significantly improve human-AI team performance," while showing AI decisions in advance increased the rate at which people followed the AI — [arXiv 2502.03482, "Can Domain Experts Rely on AI Appropriately? A Case Study on AI-Assisted Prostate Cancer MRI Diagnosis"](https://arxiv.org/html/2502.03482v1) (preprint).
- A mock-jury study (282 jurors) found most participants penalized doctors who appeared to "rubber-stamp" an AI finding, and were more lenient (more likely to believe duty of care was met) when the image had been read twice (once without AI, once with) versus a single AI-assisted read, suggesting double-reading may reduce automation bias/anchoring, though the authors frame this as theoretical — [AuntMinnie, "Can AI reduce malpractice risk for radiologists?"](https://www.auntminnie.com/practice-management/administration/risk-management/video/15819740/can-ai-reduce-malpractice-risk-for-radiologists) (secondary/trade-press coverage of a study — not the primary paper; verify before citing numbers).
- An Australian clinician survey found radiology/breast physicians preferred AI as a "second reader" (75.4% somewhat-to-extremely happy with this role) over triage (47.7%), pre-screening, and first-reader modes (26.2% each) — [CSIRO/Australian Health Review, publish.csiro.au/ah/AH23275](https://publish.csiro.au/ah/AH23275) (peer-reviewed journal article).

### Inferences
- For a UI, the clearest, most directly evidence-backed design implication is: showing a *calibrated* (not merely raw-model-score) uncertainty/confidence overlay measurably shifts clinician review behavior toward trusting high-confidence regions more and scrutinizing low-confidence regions more — this is a strong, literature-grounded justification for an uncertainty-aware overlay feature.
- The "second reader" framing (rather than "first reader" or autonomous output) is both clinician-preferred and has documented liability/accountability benefits, supporting a UI/workflow design where the AI output is explicitly positioned as a check against human judgment rather than a primary read.
- Under-reliance is a documented risk distinct from over-reliance; a UI should not assume that simply presenting accurate AI output guarantees appropriate use, since feedback alone wasn't sufficient to improve team performance in the cited study.

### Gaps
- Several findings here (Padhani & Papanikolaou review, AuntMinnie mock-jury study, UCSF uncertainty study) were accessed through secondary/press summaries rather than the primary peer-reviewed article text; the report writer should flag these as needing primary-source verification if specific numbers or quotes will be used in a final deliverable.
- No source directly measuring "appropriate trust calibration" UI elements (e.g., A/B-tested confidence-visualization designs) specific to brain tumor segmentation was found — the uncertainty-visualization evidence found is from radiotherapy/prostate/ultrasound contexts, applied here by reasonable analogy to brain tumor segmentation, not a direct brain-tumor-segmentation UI study (apart from the UCSF meningioma study, which focuses on model calibration more than UI design).

## C2. Human-factors studies on MPR + 3D view linkage usability; best-practice UX patterns for crosshair-linked viewers

### Takeaway
Direct, controlled human-factors research isolating crosshair-linked MPR interaction specifically is sparse; the one directly relevant usability study (a 2024 CBCT viewer study) found below-industry-standard usability scores and identified "accessing the MPR window" and "cursor behavior" as the most commonly reported problems, despite 100% task completion — suggesting that implementation details of crosshair/cursor interaction, not the MPR concept itself, are where usability commonly breaks down. Separately, adoption and clinical-value evidence for MPR itself is strong and old (surveys from the mid-2000s already showed near-universal radiologist use).

### Cited Findings
- A 2024 usability study had 22 participants (dental professionals) locate the mental foramen using a CBCT viewer's MPR mode; all 22 participants completed the task, but perceived usability scores were below industry standards — SUS-TR 60.68±19.58 and T-CSUQ 43.63±16.34 — categorizing the system as a "detractor"; commonly reported issues centered on accessing the MPR window and cursor behavior, plus unclear error messages — [PMC10945284, "Do Cone Beam CT PACS Viewer Interfaces Meet the Expectations of Dental Professionals From a Usability Perspective?"](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC10945284/) (peer-reviewed journal article).
- Weasis (open-source DICOM viewer) documentation describes its MPR viewer as reconstructing two complementary anatomical planes from a volumetric acquisition, with all planes kept in sync via a shared 3D crosshair that remains active regardless of which mouse tool is selected — [Weasis MPR Viewer tutorial](https://weasis.org/en/tutorials/mpr) (official tool documentation, not peer-reviewed research).
- QMENTA's multi-planar neuro-radiological viewer documentation describes a "Go To Center" control that resets the crosshair to the image's middle position — [QMENTA support docs](https://support.qmenta.com/knowledge/multi-planar-neuro-radiological-viewer) (vendor documentation).

### Inferences
- The strongest, most directly transferable finding for a real-time web tool is the CBCT study's result: MPR usability problems concentrate in *interaction mechanics* (accessing the view, cursor/crosshair responsiveness, unclear error states) rather than the underlying MPR concept, which is itself extremely well-established and expected by radiologists. This argues for investing UI polish specifically in crosshair responsiveness, discoverability of the MPR/3D-linked view, and clear error messaging, rather than in justifying MPR's inclusion at all.
- No controlled study was found that isolates "linked" vs. "independent" crosshair behavior specifically — this is a genuine open question in the literature, not just an artifact of this search, based on the explicit gap noted by the search process itself.

### Gaps
- No controlled human-factors study was found that directly compares linked-crosshair vs. independent-plane navigation, or that measures error rates/time specifically attributable to crosshair-linking design choices — this was an explicit stated sub-question and remains unanswered; a narrower follow-up search (e.g., "eye tracking MPR," "linked cursor 3D viewer usability," in *Journal of Digital Imaging* or *Radiology: AI*) was suggested by the search tool itself but not completed within this session's budget.
- Several findings (RSNA survey, 1999 MRI viewing study, pulmonary CTA study) are cited via secondary WebSearch summaries rather than directly fetched primary sources; recommend verification before stating exact percentages/years in a final report.

## C3. Provenance/audit-trail design for clinical AI outputs (model version, data hash, reproducibility) as a trust mechanism

### Takeaway
There is no single agreed standard for clinical AI provenance, but a convergent practical pattern exists across recent preprints and industry sources: version-pin the model/weights, cryptographically hash inputs/outputs (and label manifests), log inference-time settings, and link each output to the exact record/version that produced it — with the W3C PROV-O standard cited as a representational basis and a 2026 chest-X-ray "audit workbench" paper as the most concrete, directly relevant worked example found.

### Cited Findings
- A 2026 preprint describing a chest X-ray AI "audit workbench" binds each run to independent SHA-256 fingerprints of the dataset bytes, the labels manifest, and the model/weights identity, making each report "tamper-evident and reproducible," and records model identity and weights hash on every run — [symposium2026.pcshstrg.ac.th, "An AI Assurance and Audit Workbench for Chest X-ray Models"](https://symposium2026.pcshstrg.ac.th/uploads/projects/234/paper_pdf_20260715_164335.pdf) (conference paper/preprint; verify peer-review status and venue credibility — this appears to be a smaller/regional symposium, flagged for lower-confidence citation).
- A 2026 narrative review on clinical NLP provenance recommends retaining the full "production history" of each output unit — source document, extraction model, prompt, decoding settings (e.g., temperature), model version, and execution date — since identical input can yield different results under different settings/versions, and points to the W3C PROV-O standard for representing entities, activities, and agents in a way that supports audit trails and reproducibility — [arXiv 2601.19191, "Transparency-First Medical Language Models: Datasheets, Model Cards, and End-to-End Data Provenance for Clinical NLP"](https://arxiv.org/pdf/2601.19191) (preprint; verify peer-review status).
- The same review states its documentation approach aligns with established AI/clinical-reporting standards: CONSORT-AI, SPIRIT-AI, TRIPOD+AI, DECIDE-AI, and CLAIM, aiming at machine-readable documentation supporting complete reporting and reuse — [same arXiv 2601.19191 source] (preprint).
- A 2021 review of "traceability for trustworthy AI" concluded the field is fragmented: "a good number of reproducibility tools are available" but "a common approach is currently lacking, together with the need for shared semantics" — [eBuah/UAH repository, "Traceability for trustworthy AI: a review of models and tools"](https://ebuah.uah.es/dspace/handle/10017/60422) (appears to be a peer-reviewed review article or thesis repository entry; verify exact publication venue).
- An industry blog on "model provenance" recommends minimum record fields of name, provider, version/commit, checksum, and release date, arguing records should be machine-readable, human-comprehensible, and tied to versioned artifacts — [Petronella Technology Group, "Model Provenance: The SBOM for Enterprise AI"](https://petronellatech.com/blog/?p=24490) (vendor/industry blog, not peer-reviewed).

### Inferences
- For a brain tumor segmentation tool's trust/UI design, a directly actionable, literature-grounded provenance feature is: display (or make available on demand) the exact model version/weights hash used, a hash of the input volume, and the inference-time parameters for any given segmentation result — mirroring the pattern in the chest-X-ray audit-workbench paper and the clinical-NLP provenance review, even though neither source is specific to 3D tumor segmentation.

### Gaps
- No paper was found applying this provenance/audit-trail pattern specifically to a 3D segmentation or neuro-oncology AI tool; all directly relevant worked examples found are from 2D chest X-ray or clinical NLP contexts. This is an explicit gap — the provenance principles appear transferable by analogy, but no segmentation-specific provenance-design paper was located.
- The chest-X-ray audit-workbench paper's venue (a regional 2026 symposium) could not be independently verified as peer-reviewed within this session; treat as lower-confidence/preprint-tier until confirmed.
